# AGENTS.md — Multi-Agent & Subagent Operating Instructions for `familiarise_mobile`

This file defines the operational rules, module boundaries, verification gates, and MCP workflows for autonomous coding agents working in `familiarise_mobile`.

---

## 1. Golden Rules for All Agents

1. **Toolbar & SDK Paths:**
   - Flutter: `3.47.6` (`/usr/local/google/home/kaustavg/.local/bin/flutter`)
   - Dart: `3.11+` (`/usr/local/google/home/kaustavg/.local/bin/dart`)
   - Always prepend `export PATH="/usr/local/google/home/kaustavg/.local/bin:$PATH"` in non-interactive shells.
2. **Zero `JsonQueryBuilder` Policy (`prisma_flutter_connector` v1.0.0):**
   - `JsonQueryBuilder` is completely retired (`0` occurrences in `backend/lib/`).
   - Every backend repository (`backend/lib/database/repositories/*.dart`) must use typed `PrismaClient` delegates (`_prisma.<model>.*`), `_prisma.$transaction(...)`, or `BaseRepository` helpers.
3. **93-Model Web Schema Parity:**
   - `backend/prisma/schema.prisma` tracks `familiarise_web/prisma/schema.prisma` (93 models).
   - Use `./scripts/sync-schema.sh` to sync the schema and `./scripts/regenerate-build.sh --prisma` to regenerate `backend/lib/generated/`.
   - Never force-add (`git add -f`) files inside `backend/lib/generated/`.
4. **Client/Server Separation (`USE_PRISMA=false` on Mobile):**
   - The Flutter client (`lib/`) communicates exclusively with the Dart Frog backend (`backend/`) over HTTP REST (`ApiClient` / `Dio`).
   - Do not import `prisma_flutter_connector` inside `lib/`.
5. **Companion Starter Compliance (`FeatureFlags`):**
   - Keep `lib/core/config/feature_flags.dart` and `backend/lib/config/feature_flags.dart` synchronized:
     - `payouts = true`, `referrals = true`, `collaborations = true`, `wallet = true` (Companion views enabled)
     - `payments = false`, `programCheckout = false` (Paid checkout & 1:many programs hand off to `familiarise.com` via `WebHandoffDialog`)
     - `staff` is removed (Web-only in `familiarise_web`).
6. **Git Worktree Hygiene:**
   - Never create standalone `node_modules` directories in secondary git worktrees; symlink to the canonical `node_modules` if needed and remove secondary worktrees when finished.

## 3. Mandatory Verification Gate Before Committing

Before creating a commit or opening a PR, every agent must verify:

```bash
# 1. Regenerate Prisma client & Freezed/Riverpod outputs if schema or models changed
./scripts/regenerate-build.sh

# 2. Verify zero static analysis errors across both Flutter and Backend
dart analyze
cd backend && dart analyze --fatal-infos && cd ..

# 3. Verify zero JsonQueryBuilder regressions in backend
! grep -rn "JsonQueryBuilder(" backend/lib/

# 4. Run backend and frontend unit test suites
cd backend && dart test && cd ..
flutter test
```

## 4. Headless E2E Verification with MCP Servers

When verifying UI and API changes end-to-end, use the headless **Flutter Web Server** + **MCP quartet** instead of launching an Android Emulator:

1. **Dart MCP (`mcp:dart:*`):**
   - Run `analyze_files` to catch compile/lint errors instantaneously.
   - Connect `dtd` to the URI from `flutter run -d web-server --web-port 8080 --print-dtd` to call `get_runtime_errors`, `widget_inspector`, and `hot_reload`.
2. **Chrome DevTools MCP (`mcp:chrome-devtools:*`):**
   - Navigate to `http://localhost:8080`, then immediately call `navigate_page({ "type": "reload" })` once to bypass the DWDS initial blank screen (`#125`).
   - Run `evaluate_script` to click `<flt-semantics-placeholder>` so `take_snapshot` exposes the full Flutter accessibility tree.
   - Audit every user action with `list_network_requests` and `list_console_messages`.
3. **Supabase MCP (`mcp:supabase:execute_sql`):**
   - Seed deterministic `test_mcp_*` records and assert Postgres state across the 93-model schema after UI actions.
   - Always run the reverse-FK cleanup block at the end of the session.
4. **Stream.io MCP (`mcp:stream-io:*`):**
   - Provision test users (`users_upsert`), video calls (`video_create_call`), and messaging channels (`chat_create_channel`), and verify real-time chat/call state alongside DPDP recording consent (`ConsentRecord`).

See [`prompts/mcp-workflows/00-headless-mcp-harness-setup.md`](./prompts/mcp-workflows/00-headless-mcp-harness-setup.md) for the complete copy-pasteable bootstrap sequence.
