## 2. Companion Starter Architecture & `FeatureFlags`

Familiarise Mobile operates as a **Companion Starter** application compliant with Apple App Store Review Guidelines `3.1.3(b)` (Multiplatform Services) and `3.1.3(d)` (Person-to-Person Services) as well as Google Play Payments policy.

Feature flags are synchronized between `lib/core/config/feature_flags.dart` and `backend/lib/config/feature_flags.dart`:

| Flag / Surface | Companion Starter State | Behavior |
|----------------|-------------------------|----------|
| `payouts` | **`true` (Companion View)** | Consultants inspect earnings (`Earning`), payout history (`Payout`), verified accounts (`PayoutAccount`), and tax/TDS status; complex KYC/Stripe Connect onboarding hands off to Web. |
| `referrals` | **`true` (Companion View)** | Users view/share `ReferralCode`, track referral conversions (`Referral`), and inspect credit balances. |
| `collaborations` | **`true` (Companion View)** | Consultants view incoming/outgoing webinar & class co-host invitations (`Collaborator`), inspect revenue share %, and accept/decline in-app. |
| `wallet` | **`true` (Read-Only Companion)** | Users and enterprise org members inspect wallet balances and `CreditTransaction` ledgers; top-ups hand off to Web. |
| `payments` / `programCheckout` | **`false` (Web Handoff)** | Direct in-app payment capture for 1:many programs (webinars/classes) and paid checkout hands off cleanly to `familiarise.com` via `WebHandoffDialog`; free trials and pre-authorized/credit bookings complete natively in-app. |
| `staff` / `staffTools` | **Removed (Web-Only)** | Staff/admin moderation and back-office triage live exclusively in `familiarise_web`. |

## 3. 93-Model Schema Sync & `prisma_flutter_connector` v1.0.0 (`0` `JsonQueryBuilder`)

### 3.1 Synchronizing the Prisma Schema from `familiarise_web`

`backend/prisma/schema.prisma` is a real file copy (not a symlink, so Docker builds succeed on Railway) of the 93-model schema from `familiarise_web/prisma/schema.prisma`.

Whenever the web schema changes, sync and regenerate:

```bash
# 1. Sync backend/prisma/schema.prisma from familiarise_web (and verify 93 models)
./scripts/sync-schema.sh

# 2. Regenerate Prisma client, Freezed models, Dart Frog build, and Flutter codegen
./scripts/regenerate-build.sh
```

> **CRITICAL:** `backend/lib/generated/` is gitignored. Never `git add -f` generated files. Always run `./scripts/regenerate-build.sh --prisma` after cloning, pulling, or switching branches.

### 3.2 Data Access Rules (`0` `JsonQueryBuilder`)

- **`JsonQueryBuilder` is 100% retired (`0` usages across `backend/lib/`).** Do NOT introduce `JsonQueryBuilder` in any repository, service, or utility.
- Use **typed `PrismaClient` delegates** (`_prisma.<model>.findUnique`, `findFirst`, `findMany`, `findManyRaw`, `create`, `update`, `upsert`, `delete`, `deleteMany`, `count`, `groupBy`) generated by `prisma_flutter_connector` **v1.0.0**.
- For multi-step atomic mutations (e.g., slot booking, session rotation, professional background updates), use `_prisma.$transaction(...)` or parameterized SQL via `BaseRepository`.
- **Frontend Decoupling:** The Flutter client (`lib/`) does NOT import `prisma_flutter_connector` or connect directly to Postgres (`USE_PRISMA=false`). All mobile data access goes through `ApiClient` (`Dio`) to the Dart Frog backend (`backend/`).

## 4. CI/CD, Shorebird OTA, Fastlane & Railway Infrastructure

### 4.1 Branch Strategy

- `dev` — Primary integration branch for all feature/fix PRs; auto-deploys backend staging when `backend/**` changes.
- `prod` — Production release branch (mirrors `familiarise_web`); triggers production Railway deploys and Fastlane + Shorebird store releases.
- `patch/**` / `hotfix/**` — Triggers `.github/workflows/shorebird-patch.yml` for instant ~3-minute Dart-only OTA patches on Android & iOS.

### 4.2 Workflows & Deployment Configs

| File | Purpose |
|------|---------|
| `.github/workflows/flutter-ci.yml` | Runs `analyze` (Flutter 3.47.6), `test-backend` (Prisma codegen + `dart analyze` + `dart test`), `build-android`, `build-ios`, and on `prod`/workflow_dispatch runs `release-android` & `release-ios` via **Fastlane + Shorebird**. |
| `.github/workflows/shorebird-patch.yml` | Triggers on `push` to `patch/**` or `hotfix/**` (or `workflow_dispatch`) to deliver OTA Dart patches (`shorebird patch android` & `shorebird patch ios --no-codesign`). |
| `.github/workflows/deploy-railway.yml` | Triggers on `push` to `dev` or `prod` touching `backend/**`, `.railway/**`, or `.github/workflows/deploy-railway.yml` to deploy `backend/Dockerfile` to Railway and probe `/api/health`. |
| `fastlane/Fastfile` & `fastlane/Appfile` | Defines `android` (`internal`, `beta`, `production`, `patch`) and `ios` (`beta`, `release`, `patch` with `match` + `upload_to_testflight` / `deliver`) lanes. |
| `shorebird.yaml` | Configures Shorebird per-flavor `app_id`s (`dev`, `staging`, `prod`) and `auto_update: true`. |
| `.railway/railway.ts` | Configures Railway Infrastructure-as-Code (`DOCKERFILE` builder with `backend/Dockerfile`, `/api/health` healthcheck, `ON_FAILURE` restart policy, and replica settings). |

### 4.3 Update Decision Tree

```
Need to ship a change?
│
├── Backend API / Repository / Prisma query (`backend/**`)
│   └── Merge to `dev` (staging) → promote to `prod` → `deploy-railway.yml` deploys container & verifies `/api/health`
│
├── Dart-only Flutter UI / Riverpod state / bugfix (`lib/**`)
│   ├── Urgent hotfix → push to `patch/<name>` or run `shorebird-patch.yml` → live in ~3 mins via Shorebird OTA
│   └── Standard feature → PR to `dev` → promote to `prod`
│
└── Native iOS/Android change (Podfile, Gradle, entitlements, native plugin, assets)
    └── Full store release → merge to `prod` or run `flutter-ci.yml` workflow_dispatch → runs Fastlane + `shorebird release`
```

## 5. Headless Multi-MCP E2E Testing Workflow (No Heavy Emulator Needed)

All end-to-end testing can be executed headlessly using **Flutter Web Server** + **Chrome DevTools MCP** + **Supabase MCP** + **Stream.io MCP** + **Dart MCP**.

### 5.1 Three-Step Flutter Web + Chrome DevTools Bootstrap

1. **Start Backend & Flutter Web Server:**
   ```bash
   cd backend && PORT=8081 dart build/bin/server.dart &
   flutter run -d web-server --web-port 8080 --web-hostname 127.0.0.1 --print-dtd
   ```
2. **Navigate & Reload Once (Fixes DWDS Initial Blank Screen `#125`):**
   ```json
   mcp:chrome-devtools:navigate_page({ "type": "url", "url": "http://localhost:8080" })
   mcp:chrome-devtools:navigate_page({ "type": "reload" })
   ```
3. **Click `<flt-semantics-placeholder>` so `take_snapshot` Sees the Full Widget Tree:**
   ```json
   mcp:chrome-devtools:evaluate_script({
     "function": "() => { const h = document.querySelector('flutter-view') || document.body; const p = document.querySelector('flt-semantics-placeholder') || h.shadowRoot?.querySelector('flt-semantics-placeholder'); if (p) { p.focus(); p.click(); return { activated: true }; } return { activated: false }; }"
   })
   ```

## 6. Worktree & Dependency Hygiene Rules

1. **Single Canonical `node_modules`:** Never leave standalone copies of `node_modules` across multiple git worktrees. If a tool requires `node_modules` in a worktree, symlink it to the canonical repo's `node_modules` and remove the worktree cleanly with `git worktree remove` when done.
2. **Never Commit `backend/lib/generated/`:** Always regenerate locally and in CI via `./scripts/regenerate-build.sh --prisma`.
3. **Verify Both Frontend and Backend Packages Separately:** Root-level `flutter analyze` and `flutter test` only check the Flutter app (`lib/` and `test/`), not `backend/`. Always run both:
   - Root Flutter package: `flutter analyze --fatal-infos && flutter test`
   - Backend package: `cd backend && dart analyze --fatal-infos && dart test`
4. **`Platform` Enum Disambiguation:** `backend/lib/generated/` exports a `Platform` enum from Prisma (`STREAM`, `ZOOM`, etc.) that collides with `dart:io.Platform`. Always use `import 'dart:io' as io;` or `hide Platform`.
